# Fake test set with ground truth

Everything here is **invented** (names, IDs, phones, emails). No real patient data, so these files are tracked in git.
Generated by `inference/make_dummy_data.py` (deterministic; `inference/tests/test_dummy_truth.py` checks that
re-generation reproduces these files). Do not edit by hand: change the generator and re-run it.

| Tier | Docs | Purpose |
|---|---|---|
| `t1_simple` | 40 | one or two clean entities per sentence; the floor: if this fails, nothing else matters |
| `t2_formats` | 119 | one situation per document: 9 numeric/written date formats, Hebrew-calendar dates, month only, dates with prefixes (`ב-`, `מ-`), IDs (with/without context, 8 digits, dash before check digit), case numbers, 4 phone styles + landline + fax, 6 email shapes, names with prefixes/titles/hyphenated surnames, cities and organisations with prefixes, addresses, ages 45/88/89 (keep) vs 90/93/101 (mask) |
| `t3_traps` | 50 | over-masking traps: diseases named after people, the organ "לב", the verb "אושר", drugs, lab values and doses with 5+ digits, blood pressure `130/80`, ICD codes, times, generic units; and **names that are also words** (לב, אושר, גל, ניסן, אדר, שחר) next to their plain use |
| `t4_notes` | 12 | realistic discharge summaries (about 250 words): header, family, staff, the patient's name repeated in several forms (`דוד`, `מר כהן`, `לדוד`), phones, emails, dates |
| `t5_long` | 4 | 700, 1500, 3000 and 5000 words: entities at the very start, every few paragraphs and at the very end; tests window chunking and repeated values |

Files per tier: `<tier>.csv` (input for `de_identify.py`: `id,text`) and `<tier>.truth.jsonl`.

## Truth format (one JSON object per line)

```json
{"id": 1, "tier": "t2_formats", "text": "...",
 "label": [{"start": 21, "end": 31, "label": "DATE", "tag": "date-numeric-dot"}],
 "keep":  [{"start": 5, "end": 10, "note": "lab value, not an ID"}]}
```

- `label`: spans that must be masked (end exclusive; same shape as `training/` data). `tag` names the situation.
  `policy: true` marks a convention we assumed (month alone as a date, a street address as one LOC span, a passport
  number as ID): confirm it against the real annotation guidelines before calling a miss there a bug.
- `keep`: spans that must stay readable. Anything not listed in `label` is non-PHI by construction, so any prediction on it
  counts as over-masking.

Conventions (copied from `training/dummy_data`): a Hebrew prefix (ב ל מ ה ו ש) is not part of the entity, titles
(ד"ר, הגב', מר) are not part of it, first and last name are separate spans, a medical organisation includes its head
noun (`בית החולים איכילוב`), a date is one span including day, month and year. Known simplification: first names are
not matched to the grammatical gender of the sentence.

## Running and scoring

```
inference\run_dummy.bat            # runs every tier, writes inference\dummy_results\, then scores
python inference\score_dummy.py    # score again from the saved outputs (e.g. after `git pull` on the dev machine)
python inference\score_dummy.py --only t2_formats --show 30
```

The score table has, per tier, label and situation tag: `masked%` (every character covered), `partial`, `missed`,
`label%`, `exact%`, and `survive` (the truth string is still present in the de-identified text, which is the hospital's
own leak check). Below it: declared traps that were masked, extra predictions on non-PHI text, the list of leaks, and the
number of documents with offset drift (see `docs/HOSPITAL_FEEDBACK_AND_FIXES.md`, D1).
