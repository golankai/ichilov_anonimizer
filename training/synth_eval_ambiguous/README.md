# Ambiguous-words evaluation set (base model)

Invented text only; tracked in git. Generated by `training/make_ambiguous_eval.py` from
`inference/lexicons/ambiguous_words.tsv` (deterministic; `training/tests/test_ambiguous_eval.py` checks that
re-generating reproduces these files). Do not edit by hand: change the list or the generator and re-run.

**Why a separate folder.** `training/synth_eval/` holds a fixed set of files (`rare_hard`, `long`) that other tests assert.
This set has the same file shape (`id`, `text`, `label` = start / end exclusive / label), so the existing loader accepts it:

    python training/train.py ... --synth-eval-dir training/synth_eval_ambiguous      # scored like the other synthetic sets

(Not wired into `train.py`'s default yet: that is the training session's file. To score both, a one-line change there would
load two folders.) `ambiguous.meta.json` maps each id to `word`, `kind`, `tag`, `policy`, for per-word / per-kind reports.

| kind | Docs | What must happen |
|---|---|---|
| `name` | 588 | the word is a value: first/last name, month as DATE, LOC, MED_ORG, ORG (as the list says it can be): **masked** |
| `plain` | 108 | the word in its ordinary sense (`plain_example` column): **nothing masked** (every prediction is a precision loss) |
| `mixed` | 113 | name sentence and plain sentence of the same word in one document, in both orders: only the name is masked. The hard case, and the test bed for any "mask every other occurrence" rule (F8) |

Entities: FIRST_NAME 527, LAST_NAME 527, DATE 51, LOC 60, MED_ORG 56, ORG 24. Not covered: ID, INNER_ID, CONTACT, AGE_ABOVE_89
(not ambiguous words).

Conventions as in `inference/dummy_data/README.md`: Hebrew prefix outside the entity (`ב` + `חיפה`), title outside, head noun
is PLAIN TEXT, only the bare name is the MED_ORG / ORG span (`בית החולים` + `הדסה`): corrected 2026-11-09 after measuring the real data (`check_label_layout.py`); earlier versions of this set (and of `rare_hard`/`long`) labeled the head noun too, so their MED_ORG/ORG scores are not comparable with the current ones. **Dates are separate pieces** as in the real annotation (`ambiguous` month + year = two DATE spans; see `training/synth_eval/README.md`,
"Dates are three spans"). **`policy: true`** (month alone or month + year as a date; Hebrew months get Hebrew years) is a convention we assumed; the hospital counts months, the other synthetic set leaves them out.
Known simplifications: first names are not matched to grammatical gender; some co-names are themselves in the list.

Reading the numbers: group by `kind` and `word` (the meta file). A word that is masked in `name` but also in `plain` is the
over-masking case; a word missed in `name` but fine in `plain` is the leak case. 108-588 documents, one miss in a label with
24-60 examples is 2-4 points: compare means over seeds.
