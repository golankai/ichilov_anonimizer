# Synthetic evaluation sets for the base model

Invented text only (names, IDs, phones, emails): no patient data, so these files are tracked in git.
Generated by `training/make_synth_eval.py` (deterministic; `training/tests/test_metrics_and_summary.py` checks that
re-generating reproduces these files). Do not edit by hand: change the generator and re-run it.

**What this is for.** `train.py train` scores every trained model on these sets right after the real test split and
reports them separately (`results.synthetic` in `training_run.json`, and in the seed summary). They **never select the
epoch**: that stays with the real validation split.

**What this is not.** It evaluates the *base model* (token classification as it is trained). The evaluation of the *full
pipeline* (chunking, rules, post-processing on raw text) is a different thing and lives in `inference/dummy_data`
(`inference/score_dummy.py`). Different seeds and templates; no text is shared (a test checks this).

| File | Docs | Content |
|---|---|---|
| `rare_hard.jsonl` | 586 | one window each. About 40-330 examples of every label, with the rare ones on purpose: 82 ID, 74 INNER_ID, 42 AGE_ABOVE_89, 69 ORG, 77 MED_ORG, 90 CONTACT, 78 LOC. Hard cases: ID with/without context, 8 digits, dash before the check digit; phone styles, landline, fax, six email shapes; Hebrew prefixes on names, cities and organisations; hyphenated surnames; names that are also words (לב, אושר, גל, אור, שחר, ניסן, אדר); eight date formats, Hebrew-calendar dates, ranges; 40 dense form-like headers with many entities side by side |
| `long.jsonl` | 24 | 450 to 2500 words (6 each of 450, 800, 1500, 2500), several 512-token windows, entities of every kind spread over the whole text so many fall near window edges, the patient name returning in running text |

**Traps (must stay unmasked).** Ages up to 89, children's ages, and numbers of 90+ that are not ages (oxygen saturation,
pulse, weight, blood sugar), blood pressure `130/80`, score `12/15`, times, ICD codes, doses and lab values with 5+
digits, drug names, diseases named after people, generic units (`מחלקת ילדים`). Because the labels list only what must be
masked, every prediction on these shows up as a loss of precision.

**Left out on purpose** (the convention would only be our guess): month alone as a date, month + year, street addresses,
passport numbers, letter-prefixed case numbers (`H-123456`), kibbutz names, countries.

**Read the INNER_ID row with care.** The real data has only 3 INNER_ID examples (none in validation or test), so what an
INNER_ID looks like here is an assumption: a 6-8 digit case number after a label such as `מספר תיק`. A low INNER_ID score
may mean the real convention differs, not only that the model is weak.

**Statistical weight.** Counts are modest and some labels have 40-70 examples, so one miss is 1.5-2.5 points of recall
for that label. Compare means over the 3 seeds, not single numbers.

Files carry only `id`, `text`, `label` (`start`, `end` exclusive, `label`), the same shape as the real splits.

## Dates are three spans (found 2026-11-08)
The real corpus annotates a date as separate DAY, MONTH and YEAR spans (renamed DATE on load) with the separators unlabeled
(`training/check_date_layout.py`: 2097 spans, median length 2, none over 7 characters, half directly adjacent). The first version of
these sets used one span per date and scored DATE at about 0.00 while the real test split scored 0.997. The generator now splits every date
into its pieces (`split_date_spans`) and no longer produces 8-digit dates without separators. Hebrew-calendar dates are split on spaces only;
how the annotators handled them, and a Hebrew prefix inside a month word (`במרץ`), is not known.
