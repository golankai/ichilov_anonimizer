# Synthetic TRAINING documents (invented, no real data)

Generated by `training/make_synth_train.py` (deterministic; `tests/test_synth_train.py` checks the committed files).

| file | content |
|---|---|
| `synth_train.jsonl` (+ `.meta.json`) | 3000 short documents for the EXPERIMENTS: ambiguous words used as a name / as an ordinary word / both in one document, but only for the 70% "seen" words; plus ordinary first/last names, bare-name MED_ORG/ORG, dates (DAY/MONTH/YEAR pieces), IDs, entity-free documents |
| `synth_train_all.jsonl` (+ meta) | PRODUCTION variant: same recipe, but every ambiguous word is used (no held-out words). Use only with `train.py train-all`, after the recipe is settled |
| `word_split.json` | the fixed 70/30 split of the ambiguous words (hash of the word, so it never changes) |

Why a split: with 30% of the words never seen in training, `ambig_heldout` tells whether the model learned "a name needs
context" or memorised words. `train.py` reports `ambiguous`, `ambig_seen` and `ambig_heldout` for every run, with or without
synthetic data, so runs stay comparable. For the production model nothing is held out.

Conventions are the real ones (measured, see `check_label_layout.py`, `check_date_layout.py`): dates as pieces, prefix letter
outside the entity, MED_ORG/ORG = bare name only (head words such as בית החולים are plain text).
Not covered on purpose: CONTACT, INNER_ID, AGE_ABOVE_89 (rules/real data), and LOC beyond the ambiguous words.

Limits: the "ordinary use" sentences are generic frames per word category (NOT the lexicon's `plain_example`, which would put
the evaluation sentences into training), so they are less natural than real text. Name pools are disjoint from the evaluation
sets and from the fake pipeline set. Use: `train.py train --extra-train training/synth_train/synth_train.jsonl [--extra-fraction 0.5] [--staged]`.
